# BotPulse: Real-Time Web Bot Detection and Prevention
## B.Tech Computer Science & Engineering Minor Project Report

---

### Abstract
Automated programs (web bots) constitute upwards of 40% of all public Internet traffic. While search indexing crawlers provide utility, malicious and uncontrolled bots conduct web scraping, brute-force credential stuffing, API denial-of-service, and inventory scalping. Modern evasion techniques—incorporating headless browsers and rotating residential IP addresses—have rendered traditional IP-reputation and static User-Agent blocklists obsolete. This project introduces **BotPulse**, an AI-powered behavioral web bot detection engine trained across two heterogeneous datasets: the **M4D Web Bot Detection Dataset** (incorporating Apache server logs and user study data) and the **Zenodo Web Robot Detection Dataset** (comprising 67,352 real-world server log sessions). By designing a reproducible 27-feature server-log extraction pipeline, strictly eliminating target-leakage heuristics (`PENALTY`), and employing group-aware stratified splitting, BotPulse trains an ensemble classifier that achieves **92.65% accuracy** and **0.8971 Macro-F1** on held-out test data, with a real-time inference latency of **1.62 milliseconds**.

---

### 1. Problem Statement & Motivation
Web servers face relentless automated traffic. Malicious actors leverage libraries such as Puppeteer, Playwright, and Selenium to mimic human visitor behavior. Security architectures require detection mechanisms that:
1. Operate in real-time at the web server / reverse proxy layer.
2. Rely on behavioral pacing and navigational structure rather than easily spoofed client identifiers.
3. Generalize across diverse web applications and traffic profiles without suffering from target leakage or identifier memorization.

---

### 2. Dataset Integration & Methodology
A core mandate of this project is the integration of two distinct datasets into a single machine learning model:

#### 2.1 Dataset A: M4D Web Bot Detection Dataset
- Collected by researchers at ITI-CERTH (Giannakoulis et al., 2020).
- Contains Apache2 server logs and mouse movement logs across two phases:
  - **Phase 1**: 50 human sessions and 50 bot sessions browsing 61 Wikipedia articles across 5 categories.
  - **Phase 2**: 56 human sessions (generated by 28 users creating 2 sessions each) and 56 bot sessions browsing 110 articles.
- 290 total annotated sessions: 106 human, 106 advanced bot, 78 moderate bot.

#### 2.2 Dataset B: Web Robot Detection (Zenodo)
- Collected by Dorau & Rotter (2019) containing 67,352 session observations.
- Comprises 53,858 human sessions and 13,494 robot sessions.
- Features describe session duration, inter-arrival time statistics, HTTP response codes, and resource request ratios.

#### 2.3 Common Feature Harmonization
To unite the raw Apache logs of M4D with the structured tabular features of Web Robot Detection, we engineered a dedicated Apache log feature extractor. From the raw log entries:
$$\text{Log Line} = (\text{timestamp}, \text{method}, \text{URL}, \text{status}, \text{bytes}, \text{referrer}, \text{session\_id}, \text{user\_agent})$$
we derived the exact 27 server-log features matching the Zenodo schema, including:
- **Pacing**: Inter-arrival time mean ($\bar{t}$) and standard deviation ($\sigma_t$).
- **Resource Distributions**: Proportion of requests targeting images ($R_{\text{img}}$), HTML pages ($R_{\text{html}}$), CSS, and JS.
- **Navigation Graph**: Breadth ($W$, unique URLs), mean path depth ($D$), and consecutive duplicate ratio ($C$).
- **Traffic Volumetrics**: Total bytes transferred ($B$) and peak 1-second burst barrage ($B_{\max}$).

### 3. Leakage Prevention and Ethical Modeling
1. **Target Leakage (`PENALTY`)**: The Zenodo dataset includes a `PENALTY` attribute derived from a rule-based scoring formula created by the authors to filter bots. Including this feature artificially inflates accuracy to near 100% while providing zero utility on raw production traffic. `PENALTY` was strictly identified, documented, and purged from all feature matrices.
2. **Identifier Memorization (`ID`)**: Session IDs and IP identifiers were excluded from predictive features.
3. **Dataset Source Leakage (`DATASET_SOURCE`)**: Retained solely as an audit column for held-out evaluation.
4. **Group-Aware Splitting**: For M4D sessions where users completed multiple sessions (`user_0` and `user_1`), users were partitioned as atomic groups, preventing cross-split session contamination.

### 4. Experimental Results

#### 4.1 Training Set Composition
- **Total Combined Training Sessions**: 54,110
  - Contributed by M4D: **229 sessions**
  - Contributed by Web Robot Detection: **53,881 sessions**
- **Held-Out Test Set**: 13,532 sessions

#### 4.2 Algorithm Comparison on Unseen Test Split

| Model | Accuracy | Macro-F1 | Precision (Macro) | Recall (Macro) | Latency (ms) |
|---|---|---|---|---|---|
| **Random Forest** | 92.55% | 0.8963 | 86.62% | 94.47% | 75.52 ms |
| **XGBoost (Champion)** | **92.65%** | **0.8971** | **86.81%** | **94.21%** | **1.62 ms** |

#### 4.3 Source-Wise Generalization Audit
Evaluating the champion model on held-out test records partitioned by origin:
- **M4D Held-Out Subset (61 sessions)**:
  - Accuracy: **86.89%**
  - Macro-F1: **0.8578**
  - Robot Recall: **94.59%** (35 of 37 bots successfully identified)
- **Web Robot Detection Subset (13,471 sessions)**:
  - Accuracy: **92.68%**
  - Macro-F1: **0.8969**
  - Robot Recall: **96.85%**

### 5. Conclusion & Future Work
BotPulse successfully demonstrates that heterogeneous web server log sources can be unified into a high-performance, real-time intrusion prevention model. In future iterations, client-side mouse trajectory analytics and TLS fingerprinting will be integrated into the scoring engine for full defense-in-depth protection.
